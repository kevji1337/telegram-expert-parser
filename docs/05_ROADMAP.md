# Roadmap — что ещё можно сделать

## 🔴 Высокий приоритет

### 1. Полная интеграция параллельного парсинга
- **Состояние**: модуль `performance.py` готов, но `main.py` пока работает последовательно
- **Что нужно**: разделить ключи между аккаунтами (`split_keywords_across_accounts`), запустить параллельные клиенты через `asyncio.gather`
- **Ожидаемый эффект**: 2–3× ускорение при наличии нескольких аккаунтов

### 2. Парсинг комментариев для sentiment
- **Состояние**: `fetch_comments_from_posts` реализован, но не вызывается в `build_row`
- **Что нужно**: добавить вызов в `main.build_row`, считать sentiment по комментариям отдельно от автора
- **Зачем**: понять реакцию аудитории, не только тон автора

### 3. История подписчиков для точного growth_rate
- **Состояние**: `growth_rate` считается грубо (через текущий vs кэш)
- **Что нужно**: завести таблицу `subs_history` в SQLite (channel_id, ts, subs), при каждом скане добавлять запись, считать рост по полному ряду
- **Зачем**: видеть тренды (растущий / стагнирующий / падающий канал)

### 4. Telegram Premium / verified / scam флаги
- **Что нужно**: добавить в `ChannelRow` поля `is_verified`, `is_scam`, `is_fake` из Channel-объекта Telethon
- **Зачем**: автоматически отсекать scam-каналы, выделять верифицированных

## 🟡 Средний приоритет

### 5. Дашборд аналитики в веб-панели
- Графики распределения по нишам, скорам, типам
- Топ-каналы по росту подписчиков
- Heatmap по дням недели / часам публикаций
- Используем Chart.js или ApexCharts

### 6. Заметки / теги для каналов в веб-панели
- Поле `notes` в CSV + UI для редактирования
- Произвольные теги ("шорт", "лид", "ждём ответа")
- Фильтр по тегам

### 7. Экспорт в Notion / Google Sheets
- Эндпоинт `/export/notion` / `/export/sheets`
- Автоматическая синхронизация шортлиста
- Шаблон с правильными полями

### 8. Мониторинг каналов (watch list)
- Отдельный список каналов, которые перезапрашиваются раз в N дней
- Алерты при росте >X% или появлении CTA-маркеров
- Cron-задача через `scheduler` или системный cron

### 9. ML-классификация
- Заменить keyword-based classification на эмбеддинги (text-embedding-3-small)
- Натренировать классификатор `expert / brand / news / community` на размеченных примерах
- Векторный поиск похожих каналов

### 10. Анализ топа постов
- Сейчас сохраняется только ссылка на топ-пост
- Добавить анализ: какие темы попадают в топ, какая длина / формат / время публикации
- Использовать для рекомендаций "что писать в нише"

## 🟢 Низкий приоритет / nice-to-have

### 11. UI: drag-and-drop manual_review_status
- В таблице каналов колонка статуса с цветными метками
- Drag в Kanban-board: "не смотрел" → "интересно" → "связался" → "отказ"

### 12. Auth для веб-панели
- Сейчас открыта на 0.0.0.0:5000 без авторизации
- Добавить basic-auth или сессию через Flask-Login (если будем хостить публично)

### 13. Webhook-уведомления
- При завершении парсинга — слать сообщение в Telegram-бот
- Особенно полезно для длинных запусков (часами)

### 14. Сравнение каналов
- UI: выбрать 2–5 каналов → сводная таблица метрик
- Подсветка лидера в каждой метрике

### 15. Скрапинг рекламных постов
- Парсинг "tg-ads" каналов или меток рекламы
- Понять средние цены рекламы в нише

### 16. Поиск по сообществам / чатам
- Сейчас только broadcast-каналы
- Добавить поддержку чатов / супергрупп (другие методы Telethon)

### 17. Локализация UI на английский
- i18n через flask-babel
- Для возможной публикации проекта в open-source

### 18. Docker-контейнер
- `Dockerfile` + `docker-compose.yml` с volumes для sessions/cache.db/results
- Облегчит деплой на сервер

### 19. Tests
- Unit-тесты для `scoring.py`, `keywords.py`, `analytics.py`
- Mock Telethon-клиента для интеграционных тестов `main.build_row`

### 20. CLI-флаги
- `python run.py --niche AI` — парсить только одну нишу
- `python run.py --resume-from-keyword "курсы по ии"` — продолжить с конкретного ключа
- `python run.py --dry-run` — без записи в CSV

## 💡 Идеи для исследования

- **Анализ "качества" подписчиков** через парсинг участников (только для маленьких каналов из-за лимитов)
- **Кластеризация авторов** по стилю текста — найти похожих экспертов в разных нишах
- **Анализ упоминаний канала в других каналах** — proxy для популярности
- **Детект "купленных" подписчиков** через резкие скачки + низкий ERR

## Технический долг

- Глобальный singleton `parser_runner` — может стать узким местом если захотим параллельно запускать несколько парсингов из веба
- `print()` через монки-патчинг stdout — хрупко при многопоточности; лучше перевести на logging + custom handler
- `topic_clusters` в `analytics.py` — наивная частотка слов, надо TF-IDF или эмбеддинги
- Никаких retry-механизмов для отдельных постов (если упал один пост — теряем его)
- Web-панель без CSRF-защиты на POST-эндпоинтах
